# Academy activity saves

Daily Five now uses the authenticated `academy_records` runtime API. The server resolves an approved active identity and Academy entitlement. Only the six existing counters accept +1/-1, with a floor of zero, under a transaction lock. The date comes from the server in America/Toronto. Existing unrelated counters, notes and pricing evidence are preserved. A request UUID makes retries idempotent. The screen changes only after confirmation; failed loads show Retry and failed saves retain the previous count. Current-day active-member totals and their source timestamps are included in the Command Centre snapshot; absent records remain unknown.

Deck quiz answers are graded against the existing `iq_cards` options and answer key on the server. Invalid or ungradable cards are rejected. Private append-only attempt records retain incorrect answers and retries. The existing score table stores the latest answer per answered card under a distinct `deck:<id>` key, preserving volume assessment records. The denominator is answered questions, not an invented full-deck exam or certification. Answer feedback is shown only after save confirmation; failures allow retry. Quiz-score changes enqueue Command Centre reporting.

Lesson saves now reconcile the seven existing curriculum tracks from their configured chapter ranges/lists. All required chapter numbers must have recorded completions. Partial progress starts a track without marking it complete; final completion uses the recorded lesson source date. Repeated saves preserve dates. Unmarking a required chapter retains the track row and preserves the previous completion date in a private history event. This does not issue certificates or backfill fabricated historical completions. Academy's curriculum sidebar shows Not started, In progress or Completed from the saved track rows.

The API never accepts a client user/organization ID or a client score. Anonymous, suspended, unmapped and unentitled access is denied. Private records have RLS and no client table grants. No source rows are deleted, and no new provider dispatch, paid model call, notification or automation is created.

UI tests check confirmed saves, failure preservation, safe retries, server answer feedback and generated script syntax.
