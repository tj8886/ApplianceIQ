# Received Academy learning activity

The authenticated `academy_learning` API records the two existing browser events: course opens and submitted AI questions. It resolves the approved source identity and Academy entitlement, chooses the authorized organization server-side, validates the course key, and derives pillar/title from the existing course. It rejects spoofed user/org fields, arbitrary event types, fabricated completion claims and content above 8,000 characters. Receipt timestamps are assigned only after actual submission. A private sequence continues beyond retained source IDs; existing learning events are not deleted or rewritten.

Request UUIDs are checked against the existing private append-only Academy receipt history. Retries return the original receipt and source date without duplicate learning events, and conflicting reuse is rejected. The browser retains up to twenty pending events in memory with a persistent visible retry notice. Failed requests are not silently ignored. Pending events cannot be replayed under another account. The pending queue is page-local; failed events should be retried before leaving. No AI question text is stored in browser persistent storage.

Academy's analytics reads received events through the same guarded API. Users can see their own retained history; active organization owners/admins can additionally see new explicitly scoped receipts for active organization members. Historical events for other people are not assigned to an organization by assumption. The page shows the actual scope, and chapter completions exclude unmarked rows. A source save enqueues the existing bounded Command Centre worker. Its Academy evidence includes received event counts, today's received counts, source dates and an explicit basis: question submission is not model/provider completion.

The legacy Phase 3 publisher function has no active US table trigger. This change does not enable that broad publisher or claim that downstream automated coaching/model processing occurred. It repairs received-event persistence, Academy analytics and Command Centre evidence without dispatching models, provider jobs, messages or another automation. Source specifications, photos, pricing and quiz/track records are preserved.

Rollback database tests cover mapped identity, authoritative course context, source dates, idempotent replay, actor spoof/conflicting replay/false completion denial, saved analytics, foreign organization exclusion, refresh enqueue and suspended/anonymous/private-sequence denial. UI tests verify generated syntax, retained failed saves, safe confirmed retry, account-change replay denial and scoped analytics wording. All fixtures roll back; signed-in browser review remains outstanding.
