# IQ Build US cutover

The existing `project-builder-iq` site is included in the deployment registry with source `apps/iq-build`, using the reviewed US bundle builder and local ticket adapter. The Canadian source is retained. Fresh counts match across all seventeen IQ Build tables: twelve milestone templates and no saved projects, buildings, units, packages or other project records. Before schema changes, the templates' complete ordered row fingerprint matched Canada and US (`d9d96cf8efc0dc56361bcd4edf079021`). No source data needed copying or deletion.

The US application access layer requires approved mapped identity, active organization membership and store access. Projects resolve their creator and organization from the server-validated platform context. Child organization/store scope is derived from the existing project hierarchy, with indexes and RLS. Cross-org and cross-project references, parent reassignment and creator spoofing are rejected. Source CRM and SpecIQ links retain the source applications' store checks. Existing organization-specific milestone templates retain their IDs, names, dates and organization. New templates require an active organization administrator.

Projects, buildings, floors, units, packages/items, deliveries/items, appliances, milestones, contacts/team, installations and installation parts have reviewed scoped read/save paths. Activity logs and sign-offs are append-only for clients. Existing user-confirmed removal features for installation parts and unit appliances remain scoped; the migration itself deletes no records. Failed database requests propagate to the screen rather than continuing to a false success.

CRM import is now a single transaction keyed by organization and won-deal ID. It reads eligible CRM and SpecIQ source rows server-side, checks store/scope access, creates the project, packages, products and activity entry together, and returns the existing project on retry. Source package/product snapshots and source dates preserve specifications, images, pricing evidence and quote dates. Share tokens are excluded from the package snapshot. Recorded zero prices stay zero; missing source prices stay null rather than becoming invented current prices. This is a recorded source import, not an assurance of today's retailer pricing. Existing projects are not overwritten on retry.

Verification includes rollback saves through the complete hierarchy, packages/quoted source price, deliveries/appliances, milestones, contacts/team, installations/parts, immutable history, org derivation/spoof denial, cross-project package denial, foreign/suspended denial, and transactional CRM/SpecIQ import with idempotent retry and source spec/zero-price/date preservation. UI tests check generated syntax, mapped creator/context, failed-query propagation, successful results and ticket-aware boot. Registry and twelve app bundle checks pass. Signed-in browser walkthrough and real customer sign-off remain outstanding; no messages or provider/model requests are sent by verification.
