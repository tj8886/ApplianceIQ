# US password recovery

IQ Build and the main ApplianceIQ platform now expose `Forgot password?` at sign-in, leading to a dedicated `/password-reset.html` page built with the configured US public client. This page contains no analytics, AI widget or module handoff adapter. It sends recovery requests through Supabase Auth with a same-origin callback and reports request acceptance without claiming email delivery or disclosing whether an account exists. Backend failures remain failures, and repeated accepted requests have a sixty-second UI cooldown.

Only the SDK's `PASSWORD_RECOVERY` event enables new-password entry. A normal saved session is insufficient. Before update, the controller validates the current user with Auth against the recovery user. Account changes/sign-out clear recovery access. Passwords require twelve characters and matching confirmation; server password rules still apply. A failed update keeps the form available and never reports success. After success, input fields are cleared and the local session is signed out. No passwords, reset tokens or session credentials are logged or committed. Callback fragments are removed after SDK processing. Recovery callbacks sent to either application's root are forwarded to its dedicated reset page before the root client can process them.

The administrator account was verified read-only as `tjrobar5@gmail.com`, confirmed and carrying the existing `super_admin` role with a password set. The separate `tj@applianceiq.ai` account is unconfirmed and has no password set. No accounts, permissions or passwords were changed to create a shared master login.

Controller regression checks cover no unauthenticated update, malformed email, request failure/acceptance, password length/mismatch, server user validation, account switching, single successful save and failed save. The twelve generated app bundle checks verify recovery assets and US keys for both sites. Tests use synthetic values and send no recovery email.

The Supabase Dashboard redirected to its own sign-in page, so this run could not inspect the US Auth redirect allowlist or SMTP settings. Same-origin `/password-reset.html` callbacks must be allowed for `https://appliance-iq-platform.netlify.app` and `https://project-builder-iq.netlify.app`. Delivery and a real recovery-link/password update require the account holder's participation; no live password reset was performed by the agent.
