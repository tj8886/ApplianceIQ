# Academy progress and integration evidence

The Command Centre now includes recorded lesson completions, current-month lesson completions, completed tracks and started tracks without recorded completion for active organization members. Existing current-month quiz scores are retained. No progress rows means unknown, not a failing grade. The schema does not record a complete assignment denominator, so an Academy completion percentage remains unknown. Source timestamps combine dated quizzes, lesson completions and track start/completion dates; old dates are not replaced with refresh time.

The executive screen separately displays connector catalog state, organization connection/authentication state, recorded successfully completed job counts/dates, job status counts and received POS transactions per connection. A job marked success without `completed_at` does not count as completed. Catalog active/beta, valid authentication, cron dispatch and POS receipt counts are separate evidence. POS counts do not certify other imported data domains. Only a connection-error flag is published; credentials, settings, auth metadata and raw errors remain private.

Existing Academy source triggers refresh the affected organization's snapshot. Active membership changes, connection changes and sync-job changes now enqueue old/new affected organizations in the same private bounded refresh queue. No provider sync or new recurring automation is dispatched by this reporting change. Field evidence, historical snapshots, source receipts, curriculum, quiz records and recorded pricing are retained. Current executive authorization is unchanged.

`test-command-centre-academy.sql` verifies unknown missing progress, active-member scopes, date/month boundaries, retained quiz percentages, suspended-member exclusion and enqueue, configured connections versus completed jobs and actual POS receipts, foreign organization exclusion, native executive publication and private helper permissions. All test fixtures roll back. Existing Field, monthly/POS/Academy/failed-worker, Command Centre and management regressions are rerun. Frontend tests verify progress values and integration evidence wording.

The PIM consumer pass separately checks intake/publication queues and deferred receipts, live consumer code, deployed shared PIM helpers in all five bot endpoints and repeated-read/query regressions. These checks do not establish every provider's fresh completion or claim a paid model invocation or signed-in browser walkthrough occurred. The audit's source dates, deployed versions, queue totals and limitations are recorded in `command-centre-academy-verification.json`.
